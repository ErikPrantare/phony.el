#+title: phony.el
Bindings for defining voice commands in Emacs.

* Illustrative example
:PROPERTIES:
:CUSTOM_ID: illustrative-example
:END:
After having set up this package, you will be able to define voice
commands like this:

#+begin_src elisp
  (phony-defun say-hello "hello emacs"
    (message "Hello!"))
#+end_src

With such a function defined, uttering "hello emacs" will display
"Hello!" in the message area.

* Supported speech recognition backends
:PROPERTIES:
:CUSTOM_ID: supported-speech-recognition-backends
:END:
Phony currently only supports Talon for speech recognition.  If you
want to help with adding support for a [[https://www.gnu.org/philosophy/free-sw.html][Free]] backend, get in contact
through our matrix room [[https://matrix.to/#/#emacslisten:matrix.org][#emacslisten:matrix.org]].

* Setup
:PROPERTIES:
:CUSTOM_ID: setup
:END:
For speech recognition, this package assumes that you have Talon up
and running.  See [[https://talon.wiki/Resource%20Hub/Talon%20Installation/installation_guide/][steps 1-3 on their wiki]] for instructions.  If you
just want to try out phony without a speech recognition engine, see
[[#evaluating-utterances-without-a-speech-recognition-engine][phony-evaluate]].

This package is on MELPA as [[https://melpa.org/#/phony][phony]].  After installation, enable
~phony-mode~:

#+begin_src elisp
  (use-package phony
    :config
    (phony-mode 1))
#+end_src

* Usage
:PROPERTIES:
:CUSTOM_ID: usage
:END:
A language is specified through /rules/.  A rule specifies how
utterances should be interpreted.  There are different types of rules.

** Procedure rules
:PROPERTIES:
:CUSTOM_ID: procedure-rules
:END:
Procedure rules map your spoken utterances to code.  Procedure rules
are defined using ~phony-defun~.  With the following example, uttering
"hello emacs" will display "Hello!" in the message area:

#+begin_src elisp
  (phony-defun say-hello "hello emacs"
    (message "Hello!"))
#+end_src

Procedure rules can produce values.  Other rules can refer to
value-producing rules and bind their values to the arguments of the
function.  In the following code example, ~current-line~ defines a
rule matching "line" and returning the region of the current line.  It
declares ~:interactive nil~ to avoid "line" by itself to be matched,
making it only possible to match when referred to by another rule.

The two rules ~delete-current-line~ and ~beginning-of-current-line~
make use of ~current-line~ to bind their argument to its return value.
Thus, saying "delete line" will delete the current line and saying
"beginning of line" will move point to the beginning of the current
line.

#+begin_src elisp
  (phony-defun current-line "line"
    :interactive nil
    (bounds-of-thing-at-point 'line))

  (phony-defun delete-current-line ("delete" (bounds current-line))
    (delete-region (car bounds) (cdr bounds)))

  (phony-defun beginning-of-current-line ("beginning of" (bounds current-line))
    (goto-char (car bounds)))
#+end_src

For more documentation on procedure rules, see the function
documentation of ~phony-defun~.

** Dictionaries
:PROPERTIES:
:CUSTOM_ID: dictionaries
:END:
Dictionaries are utterance -> value maps.  The following code defines
a dictionary for the first five numbers:

#+begin_src elisp
  (phony-define-dictionary number
    '(("one" . 1)
      ("two" . 2)
      ("three" . 3)
      ("four" . 4)
      ("five" . 5)))
#+end_src

These are usefully referred to by procedure rules.  With the following
procedure rule, uttering "delete three lines" will delete three lines,
and correspondingly for any other number between one and five.

#+begin_src elisp
  (phony-defun delete-lines ("delete" (n number) "lines")
    (dotimes (i n)
      (delete-line)))
#+end_src

For more information on dictionaries, see the function documentation
for ~phony-define-dictionary~.

** Open rule
:PROPERTIES:
:CUSTOM_ID: open-rule
:END:
An open rule is a way to match on any one of multiple rules.  In the
following code example, one may utter "delete line" to delete the
current line, or "delete sentence" to delete the current sentence:

#+begin_src elisp
  (phony-defun current-line "line"
    :interactive nil
    (bounds-of-thing-at-point 'line))

  (phony-defun current-sentence "sentence"
    :interactive nil
    (bounds-of-thing-at-point 'sentence))

  (phony-define-open-rule region
    :alternatives (current-line current-sentence))

  (phony-defun delete-current ("delete" (bounds region))
    (delete-region (car bounds) (cdr bounds)))
#+end_src

Instead of explicitly listing all alternatives, other rules can add
themselves to an open rule.  This is a good way of providing
extensibility for your grammars.  The next code example is identical
in effect to the previous one:

#+begin_src elisp
  (phony-define-open-rule region)

  (phony-defun current-line "line"
    :contributes-to region
    (bounds-of-thing-at-point 'line))

  (phony-defun current-sentence "sentence"
    :contributes-to region
    (bounds-of-thing-at-point 'sentence))

  (phony-defun delete-current ("delete" (bounds region))
    (delete-region (car bounds) (cdr bounds)))
#+end_src

Note also that ~:interactive~ defaults to ~nil~ when ~:contributes-to~
is provided.

For more information on open rules, read the function documentation
for ~phony-define-open-rule~.

* Standard library
:PROPERTIES:
:CUSTOM_ID: standard-library
:END:
The standard library provides some basic rules that can be useful for
defining commands.

- ~word~, ~phrase~ matches a word or a sequence of words,
  respectively.  Both return a string.
- ~digit~ matches a digit, e.g. "one", "eight" and "zero".
- ~number~ matches a number.  Examples of numbers are "five" (5)
  "twelve" (12), "one hundred one" (101), "five zero five" (505),
  "thousand three hundred thirty seven" (1337) and "one thousand and
  three hundred and thirty seven" (1337).
- ~letter~ matches a letter.
- ~non-alphanumeric-character~ matches a graphical character that is
  not a letter or digit.
- ~graphical-character~ matches a graphical character (letters,
  digits, and other visual characters).

#+begin_src elisp

#+end_src

* Evaluating utterances without a speech recognition engine
:PROPERTIES:
:CUSTOM_ID: evaluating-utterances-without-a-speech-recognition-engine
:END:
Use the function ~phony-evaluate~ to evaluate an utterance, given as a
string.  Phony will try to parse the utterance as a sequence of
interactive procedure rules, and evaluate them in order.

~phony-evaluate~ is unstable, and its behaviour may change in the
future.
* Customizing rules for matching
:PROPERTIES:
:CUSTOM_ID: customizing-rules-for-matching
:END:

You can change =phony-parser-literal-comparator= to a function that
compares the input token with the token from the rule. For example,
the following code ignores case and punctuation.

#+begin_src emacs-lisp :results none
(defun my-phony-parser--sanitize (s)
  "Lowercase and remove punctuation."
  (string-trim (replace-regexp-in-string "[-,\\.!?:]" "" (downcase s))))

(defun my-phony-compare-literal (a b)
	"Ignore case and ending punctuation."
	(string= (my-phony-parser--sanitize a)
					 (my-phony-parser--sanitize b)))

(setq phony-parser-literal-comparator #'my-phony-compare-literal)
#+end_src

* Authoring libraries
:PROPERTIES:
:CUSTOM_ID: authoring-libraries
:END:
** Modules
:PROPERTIES:
:CUSTOM_ID: modules
:END:
Libraries defining phony rules for other users are organized in
/modules/.

By default, rules in modules are made non-interactive and do not
contribute to open rules outside of the module.  For rules in modules
to be interactive and to contribute to open rules, they have to
explicitly be enabled with ~phony-enable-module~.  This ensures that
library rules do not interfere with the spoken commands of the user
unless they explicitly enable the library.  It is recommended for
library authors to put ~phony-enable-module~ behind a global minor
mode, so that enabling and disabling modules behave the same as
enabling and disabling modes.  See the documentation of ~phony-module~
and ~phony-define-module~ for more information on modules.

** Interface rules
:PROPERTIES:
:CUSTOM_ID: interface-rules
:END:
Interface rules, or simply /interfaces/, allow users to override
certain rule definitions, or to substitute your definitions for those
in another module.  Interfaces are defined using
~phony-define-interface~.  Interfaces are how the standard library
allows users to switch out the standard implementation with the
implementations in talon community by using ~phony-provide-from~.

Rules that implement interfaces are called /providers/.  Providers are
specified by using the ~:provides~ keyword argument in a rule.
Providers that are not part of any module take precedence in interface
resolution, so that the providers defined in the configuration of a
user are selected automatically.

See the documentation of ~phony-define-interface~ for details
on interfaces.
